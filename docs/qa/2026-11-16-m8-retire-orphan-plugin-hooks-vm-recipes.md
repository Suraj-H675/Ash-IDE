## Consumer-traced cleanup

The preceding M8 change removed the live application-plugin `agent.tool.before` / `.after` dispatch and Claude tool decision protocol. The remaining Orca `plugin-hook-participants.ts` imported an app-plugin-only `agent-tool-call-reader.ts`, and a now-unregistered plugin runtime binder still installed the plugin hook runner and resident worker warmer. Also, `plugins.ts` (unregistered) still wired a `plugins:editorSaveHook` IPC handler; the active generic RPC error mapper still imported `PluginHookDeniedError` from the orphaned plugin hook dispatcher. Finally, Main's registered VM recipe handlers still imported plugin-provided recipes despite being registered with **no plugin service**.

**Removed:** the orphan plugin worker-hook participant registry, app-plugin tool-call parser and terminal resolver, editor-save hook IPC handler, approved plugin VM recipe augmentation module, and orphan plugin hook dispatcher. Each of those **five inherited Orca sources** has its original upstream source SHA-256 and specific M8 exclusion reason recorded in `docs/provenance/ash-exclusions.json`. Their last import/callers are disconnected from the dormant plugin runtime binding, dormant plugin IPC registrar, the registered VM recipe handlers, and the live RPC error mapper. The active RPC mapper still handles normal invalid-argument, browser, emulator and runtime errors.

The registered `ephemeralVm:listRecipes`, `listRecipeCatalog`, `doctor` and `provision` handlers no longer source **global application-plugin** recipes; their recipe lookup remains **repository-owned** via the project's existing `orca.yaml` recipes. The pure recipe-context helpers no longer merge in plugin content packs, and saved runtime recipe snapshots still take precedence over a current repository recipe. This is removal of plugin injection from a legacy registered route, **not** an assertion that remote-development/VM provisioning is approved or that the full excluded remote-development subsystem has been removed.

**Retained:** local repository configuration parsing and diagnostics, original-folder-first project context, ordinary editor save and Monaco, Git/worktree and terminal/agent operations, RPC argument/error mapping, provider-native Claude/Codex status/ownership/permissions, native skills/MCP/hooks, Chromium browser extensions, persistent daemon and independent user data. No real user repository, provider account, credentials or unrelated application data was edited.
