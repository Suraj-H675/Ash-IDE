# M8 test runner audit repair

Reviewed branch `fix/m8-restore-test-runner-audit`, based on `919c05de50d9e525cc0c27eaacbf463e4cf0cfa7`. The baseline reported 70 stale runner diagnostics and 15 test-like files without collection.

## Discovery and corrections

The audit uses Vitest's file-only listing with the root config under both the Node CLI and the Bun-backed package wrapper. Both use `UNIT_INCLUDE`. Ordinary local runs use Vitest's default exclusions and balanced runs add `UNIT_EXCLUDE`. The audit also lists the dedicated agent-status benchmark config separately. It follows runtime imports and re-exports from these real entrypoints, removing type-only edges before crediting test registrars.

Foundation uses exact Vitest selectors and directly executes `linux-package-file-permissions.test.cjs` with Node. The audit reads those commands from the workflow, checks selectors against the corresponding runner and checks that the Node file exists. On this diff, foundation selects 131 entry files. Local Vitest selects 2,232 more, and the agent-status benchmark has its own manual entrypoint. These figures describe collection. Hosted results and individual platform skips require actual test runs.

The audit requires eight named foundation test groups covering Linux package permissions, audit diagnostics, runtime and provider boundaries, native PTY routing, IPC, WebSocket authentication, excluded renderer capabilities, and package inputs. It also requires exactly one runnable, non-conditional and non-failure-tolerant `Verify runnable test collection` quality-gate step; deleting or silencing that step must be detected by the still-required audit regression suite. It reports a missing group, a conditional job or test step, unsupported test commands, and zero hosted entries as drift. It reads the individual selectors from the workflow, so those can change without updating a second file list. The contract checks static collection from direct root-relative Node commands under the default shell. Hosted execution and outcomes still require a workflow run.

Ash entrypoints now invoke the retained Git, structured launch, Pi option refresh and terminal replay registrars. The Pi fixture supplies an empty journal status to the actual host recovery reader. The terminal replay uses retained recordings and runs without launching any agents. Two unreferenced registrars belonged to the retired mobile web app and application-plugin marketplace, so both were removed with their pinned attribution. The original Git compatibility wrapper remains excluded and the four retained Git case modules run against a temporary repository through the new Ash entrypoint.

## Verification

- **Pass** — `CI=1 NODE_OPTIONS=--max-old-space-size=4096 pnpm run check:test-file-runners` with pinned pnpm 12.14.0. The earlier disposable orphan spec made the command exit 1 and name the orphan. The regression suite still checks runtime re-exports, type-only edges, orphan specs and registrars, a missing config, stale selectors, and Node execution versus syntax checks.
- **Pass** — 71 tests in five focused Node Vitest suites, including 12 Git compatibility cases on Git 2.56.1. Before the fix, all eight new negative cases failed because the audit returned an empty diagnostics list. They cover zero hosted commands, a wrapper-only workflow, removing the audit step while other groups remain, replacing a required group's command with a pnpm wrapper, a shell condition or a non-test command, and disabling a group or the job with `if`. The same tests pass after the fix. The positive case credits both direct Vitest and direct Node commands from the checked-in workflow. Four additional reviewer-held-out negative cases reject removing the audit gate, masking its exit status with `|| true`, making it failure-tolerant, or enabling `continue-on-error` on a required test step. The unmodified audit had incorrectly accepted removal of its own quality-gate step.
- **Pass** — all five TypeScript projects, changed-file oxfmt and oxlint checks, and `git diff --check`. The provenance verifier checked 33,506 source records, 698 adaptations, and 8,870 removals against the unchanged MIT license. The stock invocation hit `spawnSync git EPERM` in the sandbox. A temporary preload gave only the verifier's read-only Git index query inherited stdin, and the verifier then exited 0.
- **Prior run** — the dedicated agent-status benchmark passed its one test, and the Linux package permissions fixture passed when executed directly with Node.
- **Local setup limitation** — offline package materialization with pnpm 12.14.0 succeeded with lifecycle scripts skipped after the full install tried to fetch Node headers for Windows native workspaces. The pinned Bun postinstall and the process-host build were run separately. The lockfile stayed at the reviewed version.
