## Release gap confirmed against the previously shipped package

The approved product excludes a general IDE application-plugin marketplace, worker host, authoring framework, and runtime plugin bundles (EX-03 and PK-08). **Not excluded:** Chromium browser extensions and their native host, provider-native MCP/skills/hooks, built-in language services, local agent-browser tooling, and the ordinary terminal/renderer/daemon runtime. The previous packaging stage removed voice workers and retired speech/app-plugin **CLI commands**, but actual `app.asar` still contained the executable `out/main/plugin-host-entry.js`, `out/main/plugins/plugin-authoring-checks.js`, and four `resources/plugins/declarative/*.mjs` files. Native `resources/plugins/launch` and plugin-authoring type bundles were also copied under separate `resources/plugins` destinations. Two bundled general application plugins and an `orca-marketplace.json` catalog were shipped, despite no application-plugin service being created by current Ash main startup. The renderer's onboarding theme fixture imports selected theme JSON at **build time**; it does not require the original plugin directories at package runtime.

## Deliberate implementation boundary

- Electron-builder no longer copies `resources/plugins/launch` or authoring `.d.ts` files as native `extraResources`, and no longer runs verification that **requires** excluded application-plugin bundles. It keeps agent-browser skills and native chat resources, as well as browser-extension and agent-hook executables.
- `config/excluded-ash-app-plugin-artifacts.cjs` declares two reviewed standalone executable files, the retired `resources/plugins` source tree and `plugins` native-resource tree. The package globs exclude those exact runtime artifacts, and `asarUnpack` no longer selects plugin-host entrypoints, plugin authoring checks or declarative test harnesses.
- The independent `verify-ash-packaged-asar-hygiene.cjs` guard rejects the retired executable **both inside ASAR and in `app.asar.unpacked`**, the `resources/plugins` source tree anywhere inside ASAR or its unpacked shadow, and any native `resources/plugins` extra-resource tree. These are separate checks from the package selection config, so accidental future reintroduction fails the build rather than shipping silently.
- New synthetic negative fixtures cover standalone packed/unpacked workers, marketplace catalogs, declarative runtime and plugin authoring types, and native extra-resource copies. A real electron-builder `FileMatcher` fixture verifies that the exclusions work as *globs*, retaining daemon entry, native Chromium browser-extension host, agent hook entry and compiled renderer assets; static config assertions check Linux, macOS and Windows resource mappings.
- **No mass deletion of shared plugin source code or `out/main/chunks`**: these compiled chunks need a separate reachability and runtime-activation review. The compiled renderer can retain static onboarding theme fixture assets without enabling general application plugin installation. This is a deliberate, independently testable packaging slice, **not full EX-03 acceptance**.
