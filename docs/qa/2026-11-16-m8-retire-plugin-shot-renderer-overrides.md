## Consumer trace and implementation

Previous M8 milestones excluded the general application-plugin host, screenshot IPC/RPC registration, marketplace, plugin editor selectors and custom frames. A source importer audit identified a closed 19-file renderer group still implementing `orca plugin shot` view requests, declarative replay, editor capture status and one-shot appearance overrides. The plugin view request handler was **not registered or imported by Ash's live preload/startup**. However, its global capture state still affected four retained renderer surfaces: application appearance, right-sidebar width, Floating Workspace toggle visibility and an unconditional root plugin-shot replay mount.

**Removed from live paths:** `usePluginViewCaptureStore` from `useSettingsDarkTheme`/`useDocumentDarkTheme`; the screenshot-only width override from `RightSidebarInner`; the screenshot-only Floating Workspace suppression from `AppWorkspaceShell`; and `PluginShotReplayMount` from `App`. The retained theme resolver (`resolvePaintedDark`, including Match Terminal), system-color preference hook, persisted sidebar width/clamping, Floating Workspace toggle, native browser/Design Mode and extension installation dialog remain unchanged.

**Deleted:** the 16 `src/renderer/src/components/plugins/view/*` plugin screenshot/act/replay modules, `src/renderer/src/store/plugin-view-capture.ts`, `src/renderer/src/store/plugin-shot-replay.ts`, and `src/renderer/src/components/editor/plugin-editor-capture-status.ts`: **19 inherited Orca sources**. For each, the source exclusion ledger records its exact pinned original SHA-256 and specific removal reason. This does **not** remove the general browser screenshot/automation pipeline or the other still-dormant plugin panel and worker modules. No user files, real profiles, provider configuration, credentials or other app data were edited.
