## Consumer-traced removal

The live Main hook listener still forwarded accepted Claude and other native-agent tool observations to Orca's general application-plugin `agent.tool.before` / `.after` runner, which could respond with a `PreToolUse` deny or rewritten tool input. The Claude POSIX managed script also captured the HTTP response, waited for a plugin decision, and potentially printed a `hookSpecificOutput` approval override. Ash had already excluded the application-plugin host, worker, installer, marketplace and preload namespace, so this legacy tool interception was not an approved capability.

**Removed:** the tool decision invocation from the live `AgentHookServerLifecycle` after normal status handling; Claude's `decidesPreToolUse` flag, special decision-header POST path, response capture and delayed output; the unused `decisionHeaderVar` option of the shared hook-post command generator; and the two inherited application-plugin decision modules `agent-tool-plugin-hooks.ts` and `claude-hook-decision-script.ts`. Both deleted files have their exact pinned original SHA-256 recorded in the upstream exclusion ledger. Updated the local agent-hooks README to describe Ash's actual behavior instead of Orca's retired tool-hook marketplace.

**Preserved:** authenticated hook-token checks, pane ownership and fresh-status disposition, recognized provider events, tool/status observations, transcript retry, assistant activity, slowloris/interference recording, prompt-claim and Claude agent-view routes, and the existing provider-native approval/permission mechanisms. The POSIX Claude managed hook now prints neutral `{}` before posting and continues using the usual metadata, curl, replay-guard and offline spooling paths. It cannot accept an HTTP `PreToolUse` decision from an excluded general app plugin. Windows Claude scripts already printed neutral output and remain on their provider-native path. This change does not remove Codex/Claude provider hooks or ordinary permission prompts.

The inactive inherited plugin hook-participant and tool-call-reader source modules remain separate follow-up debt. Their references do not restore a registered Main app-plugin service. No user repository, credential, installed provider configuration or other application's data was edited.
