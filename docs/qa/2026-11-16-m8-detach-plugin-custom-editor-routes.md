## Dependency trace and implementation

Despite removal of application-plugin Main IPC, preload, settings/marketplace and save hooks, Ash's **live primary file-editor UI** still allowed plugin custom editors to take over text or byte documents. The normal editor panel called `useFileCustomEditors`, the render model exposed `plugin-editor:*` modes, the content surface conditionally mounted `PluginCustomEditorFrame` and `PluginBytesCustomEditorSurface`, and tab icons and hover titles could be plugin-contributed.

The normal editor panel now requests only built-in view modes, and its render model no longer accepts or advertises app-plugin custom editors. The editor content, edit-file surface, header, view-mode toggle, panel shell and file-tab chrome no longer render general app-plugin frames, selectors, titles or contributed icons. The existing file-type icon and retained mode icons are used in tabs. The custom editor mode helper `view-mode/custom-editor-toggle.ts` has been deleted, with **exact upstream SHA-256** `f049ea674fd251884873f01dda389c01003c5b57e444ae06711fd5f52b6b65cb` recorded in the source exclusion ledger.

**Preserved:** Monaco source editing, built-in Markdown rich/source and table of contents, CSV/paged CSV, SVG, Mermaid, notebook, image and media viewers, diff/changes modes, editor tab drag/rename/hover and file-icon behavior, panel source/rich toggle, queued editor flush before mode changes, byte-file fallback and the original file save/format/recovery protections. **Not removed in this slice:** lower-level plugin byte-draft/save machinery, plugin custom-frame components used by orphan plugin view routes, and plugin-only host/store types. These require a separate consumer/recovery audit; an ASAR size reduction is not proof that all frames or plugin code have been eliminated.

## Remaining acceptance limits

This milestone closes **general application-plugin takeover of the normal editor panel, content surface, view-mode toggle and tab icons**. It **does not yet remove every lower-level plugin custom-frame module** reachable from retained binary-draft compatibility or orphan view-request routes; those need a separate import/runtime graph and source provenance review. The renderer tests render real React surfaces with stubbed built-in viewers and synthetic plugin frames; the native package checks are true X11/Wayland lifecycle, PTY, browser and notification smokes, **not** full interactive editing/saving visual parity in both desktop environments. Real-provider authentication/approvals, independent multi-window stress, updater rollback, Windows/macOS package verification and signing remain open; M8/EX-03/ED-03/ED-07/PK-08 are not fully accepted.

This document records **candidate evidence**. Fast-forward integration, post-integration tests/typecheck/provenance, remote push and exact-successor GitHub CI must be independently observed; the linked success above is for the base commit only.
