# M8 trusted update preflight

**M8 remains NO-GO for update activation.** Ash has no approved release signer or feed, no complete compatible-state rollback, and no exclusive runtime maintenance fence. The desktop updater status remains unavailable. No installer, download, restart, or background update path is registered.

## Package identity evidence

The Linux packaging hook checks `app.asar` and the unpacked CLI `package.json` before it writes `resources/ash-package-input-identity.json`. It bounds the archive to 512 MiB and rejects a malformed or over-16-MiB ASAR header before `@electron/asar` materializes the entry list; the parsed list is then limited to 100,000 entries. It reads package metadata from a private copy, rejects duplicate or traversing archive paths, and refuses linked package entries and linked input files. It keeps the inspected file descriptors open and synchronously rechecks that both paths still name the same single-link files with unchanged snapshots after the temporary sidecar is synced and immediately before its atomic rename. The input claim identifies its evidence as `packaging-input-snapshot`; its `captured*Sha256` fields hash the bytes copied or read by the hook. They do not claim to hash the bytes later consumed by Electron Builder or the final AppImage. A same-user process can still mutate the mode-0700 inspection copy while `@electron/asar` reads it or the build tree after the final check, so the claim never establishes final payload identity.

The offline AppImage staging tool verifies the signed manifest, the full AppImage digest, and its Linux architecture. It can also check that a signed package-input claim matches the signed release manifest. It does not inspect the candidate's SquashFS payload or compare the input claim hashes with the embedded files. `candidateIdentity.state` therefore remains `unverified`, `ashPackageIdentityVerified` remains `false`, and activation remains unavailable. A verified outer artifact digest is not proof of the embedded Ash version.

The builder supplies the product name and app ID from Ash's packaging contract. Those values are not independently extracted from `app.asar`. The build input claim is provenance evidence, not a production signature or a payload identity claim accepted for installation.

## Runtime census

Trusted desktop IPC exposes `updater:getPreflight` through `window.api.updater.getPreflight()`. The handler counts Ash windows and reads sessions from daemon adapters that are already authenticated and connected. Each request is read-only, has a bounded timeout, and never reconnects a daemon. It rechecks daemon incarnation and provider identity before returning a count. A changed or partial inventory stays unknown.

The report separates windows, daemon PTYs, PTY-owned agent sessions, provider agent sessions, pending disk writes, daemon generations, and exclusive host ownership. It does not return agent identity digests. Provider-wide agent inventory, pending disk writes, and exclusive host ownership remain unknown, so the report always defers when observed counts are zero. Known live windows, PTYs, or PTY-owned agents produce a busy result. There is no ready result.

Settings → Updates exposes a read-only **Inspect local update blockers** action while Ash update status is unavailable. It displays the admission decision, candidate evidence, per-domain counts or unknown reasons, and blocker explanations. It runs only when requested; it does not check for releases, download, install, restart, stop sessions, or modify files. If the desktop runtime cannot return a complete report, the UI says the report is unavailable and keeps update status unavailable.

The desktop runtime report currently has no staged candidate and labels that state `candidate-not-provided`. Offline staging produces a separate unverified candidate-identity result; no approved trust root or safe candidate-to-runtime admission path joins the two results.

The web preload rejects this desktop-only diagnostic. The updater remains unavailable; the Ash unavailable-status UI branch exposes no update installation, download, restart, or stop-runtime action.
