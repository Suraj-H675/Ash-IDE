# M8: reusable two-version packaged-profile recovery QA

**Acceptance scope:** additional PK-06 evidence for **disposable SQLite profile state** only. This is not an installer, complete mutable-state rollback, schema migration, release-signature verification, or maintenance fence. PK-05, PK-06 and RT-15 remain **production NO-GO**.

## Verified journey

`config/scripts/desktop-distribution/release/verify-two-version-packaged-profile-qa.cjs` accepts two independently generated Linux AppImages, their corresponding `linux-unpacked/resources` directories, two reports from the pinned SquashFS embedded-identity QA verifier, and independently pinned versions and outer SHA-256 hashes. It requires a strictly increasing, different version. Before launching either compiled CLI, it verifies each full AppImage digest and compares its diagnostic report, embedded version, app ID, unpacked `app.asar` hash, and compiled CLI package-metadata hash against the associated packaging-input identity claim. Identity reports explicitly remain `unverified` for production authentication and cannot authorize activation.

The harness creates a private disposable home, runtime directory and single-profile SQLite database with an unrelated provider-data sentinel. It exercises the **compiled CLI taken from the packaged `app.asar.unpacked/out`**, not test-mocked handlers: previous-version SQLite write and checkpoint, candidate-version read/write and checkpoint, previous-version rollback, and both-version reads of the restored state. It checks retained state, checkpoint location/mode, unrelated sentinel integrity and isolated cleanup. The profile fixture is never a real Ash or Orca installation. The packaged CLI files are from the accompanying build output; matching the ASAR and metadata checks is not a cryptographic proof of every unpacked file's identity.

The companion Vitest file `verify-two-version-packaged-profile-qa.test.mjs` has an always-on argument-contract test and environment-gated genuine-image positive/negative tests. Supply `ASH_M8_QA_PREVIOUS_RESOURCES`, `ASH_M8_QA_CANDIDATE_RESOURCES`, `ASH_M8_QA_PREVIOUS_ARTIFACT`, `ASH_M8_QA_CANDIDATE_ARTIFACT`, `ASH_M8_QA_PREVIOUS_REPORT`, `ASH_M8_QA_CANDIDATE_REPORT`, `ASH_M8_QA_PREVIOUS_VERSION`, `ASH_M8_QA_CANDIDATE_VERSION`, `ASH_M8_QA_PREVIOUS_SHA256` and `ASH_M8_QA_CANDIDATE_SHA256` to exercise the actual packaged pair. The standalone script accepts the corresponding ten `--` flags. With no real fixture environment it does not silently claim the genuine-image proof: Vitest marks those cases skipped.

## Evidence and limitations

The initial reusable harness and its companion test passed against genuine isolated Linux `0.1.0` and `0.2.0` AppImage builds: the real fixture run passed **3/3 tests, zero skips**, including negative version, digest, report mismatch and downgrade-order checks. The disposable `0.2.0` candidate was built with a dirty version-only source change, so its embedded `sourceCommit` is `null`; it is not a signed or source-proven release. The earlier one-off script had independently demonstrated the same SQLite journey; this checkpoint turns it into a maintainable regression. Exact private fixture paths, hashes and command receipts remain in the private handoff, not public Git.

This does **not** replace the application executable on disk, verify startup of the candidate on a migrated installed profile, roll back all user data/settings/browser/agent history, or prove runtime quiescence. Further PK-06 acceptance requires actual cross-version installed-application and compatible full-state recovery, with session/write admission and fresh security review. No production updater state or user profile is touched or activated here.
