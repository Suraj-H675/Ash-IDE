## Reviewed importer chain and change

Earlier M8 removal detached general app-plugin file types from the normal static New Tab dropdown and Cmd+J palette. The **live searchable New Tab quick-create menu** still called `usePluginNewFileMenuOptions` from `TabBarInner`; it loaded the excluded app-plugin new-file store, inserted dynamic `new-plugin-file` rows through `withPluginNewFileMenuOptions`, drew untrusted plugin-contributed icons and dispatched a special plugin document creation action. This violated the approved complete removal of the general app-plugin UI.

`TabBarInner` now passes the existing built-in `useTabBarCreateMenuController` directly to the unchanged surface. Deleted the plugin-only wrapper `use-plugin-new-file-menu-options.ts` and its original pinned SHA-256 `10f3b56b30acdfbec825a24b85f1b5d98734d9ae9b8010da4858803398fd5bc3` is documented in `docs/provenance/ash-exclusions.json`. Deleted the obsolete plugin file type/property/append helper from `tab-create-menu-options.ts`, its icon branch from `TabBarCreateEntryRow`, and its redundant switch case from the built-in menu controller.

**Preserved:** built-in searchable New Terminal, browser, New Markdown, Open Markdown and Windows PowerShell/other supported shells; search matching, token scoring and oversized-query protection; normal panel and tab selection, real file browsing, text editing and editor-save transaction/byte-draft recovery. The remaining `store/plugin-new-files.ts`, `store/slices/editor/actions/untitled-file-creation.ts`, and related binary-draft or plugin compatibility code are **not** removed here until a separate no-data-loss importer/recovery audit. No actual user files, source repos, browser profiles or provider account configurations were edited.
