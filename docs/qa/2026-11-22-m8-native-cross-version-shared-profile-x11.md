# M8 — genuine two-version native X11 shared-profile recovery QA

**Scope:** additional diagnostic evidence for PK-06 only; **PK-05, PK-06 and RT-15 remain production NO-GO**. The application updater stays unavailable. This is a manually invoked, QA-only test, not an executable replacement, update activation, production migration, or full-state rollback.

## Native journey and evidence

`config/scripts/desktop-distribution/runtime-verification/verify-linux-appimage-cross-version-profile-x11.sh` runs on Linux with a private authenticated Xvfb screen and a disposable home, XDG directories, provider homes, runtime, project and profile. It accepts two genuine built AppImages with caller-pinned exact SHA-256 digests, strictly ascending version pins, and an independently pinned SquashFS reader. The test copies and independently verifies each full AppImage in its private fixture, checks its embedded package identity, then extracts **Node, CLI, supporting modules and dependencies directly from that image** using the pinned SquashFS reader. It does not use the adjacent, potentially stale `linux-unpacked` output to execute profile operations. Before extraction, the SquashFS manifest must contain only real files and directories in every tree to be executed or loaded; symlinks and special files are rejected, and the extracted tree is traversed again before use. These offline checks establish which bytes were tested, **not production release authenticity**.

It seeds a single private SQLite profile, takes a checkpoint through the **previous version's packaged CLI**, then performs these real desktop launches against that **same** test profile:

1. **Previous-version AppImage:** real Ash X11 window, authenticated runtime status and Settings RPC, then the test-owned terminal daemon and runtime stop.
2. **Candidate-version AppImage:** accepts the previously initialized database with all desktop-added default fields, observes a supported settings change, provides a real X11 window and authenticated Settings RPC, then stops its own daemon and runtime.
3. **Previous-version AppImage again:** after the previous CLI restores its retained private checkpoint, starts the real desktop and reopens the restored SQLite state.

The verifier asserts the actual app versions reported by the authenticated runtime, native Ash window identity and the reported app PID matching the pinned AppImage launch child, three distinct runtime identities, three successful daemon stops **and observed normal exits after each graceful runtime stop**, private checkpoint permissions, restored supported SQLite settings, and retained unrelated fixture state. A `runtime.stop` response of `stopping` is not by itself sufficient for PASS; the test waits for that exact pinned process to exit and requires a successful process wait, without fallback termination. The `ash-two-version-native-pidfd.py` helper records process start ticks and binds any fallback cleanup signal to the specific Linux pidfd after checking owner and fixture process identity; there is no numeric-PID kill fallback. Private logs remain in the disposable fixture for inspection. A successful run returns zero, and the fixture's daemon PID record must be absent.

The authentic local X11 fixture run passed with genuine `0.1.0 → 0.2.0 → 0.1.0` AppImage versions using their embedded helper/runtime bytes. All stages opened real windows and read settings through the authenticated IPC boundary; SQLite rollback succeeded, the exact three AppImage processes exited without fallback termination, and the final test-owned process audit found no surviving process. The `0.2.0` candidate is a **disposable, version-only dirty-source build** with a null embedded source commit, not a cryptographically sourced or production release. Exact private fixture paths and process receipts are intentionally omitted from public source. The supported theme preference is written and checked in SQLite; this does **not** establish user-initiated Settings interaction or rendered theme parity.

The helper `ash-two-version-native-profile-qa.cjs` performs data/identity assertions and delegates ownership-checked cleanup through `ash-two-version-native-process-cleanup.cjs` to the pidfd tool. `ash-two-version-native-embedded-fixture.mjs` verifies and extracts the exact in-image helper bytes. Foundation CI runs shell/Node/Python syntax checks and a focused negative regression checking forged daemon/GUI/Xvfb identities and that a **live** process cannot pass the natural-exit check. CI **does not** claim to execute the private native Xvfb/AppImage fixtures. The full real-image native journey passed separately. Manually invoke the native test with positional arguments `PREVIOUS_APPIMAGE PREVIOUS_SHA256 PREVIOUS_VERSION CANDIDATE_APPIMAGE CANDIDATE_SHA256 CANDIDATE_VERSION PINNED_SQUASHFS_READER`.

## Remaining work

This QA transition did not replace an installed executable, test a signed Ash feed, preserve live provider-native agents during maintenance, compare every mutable state domain, validate arbitrary schema migrations, run actual installed downgrade/recovery, or prove a transactional exclusive admission fence. It cannot satisfy production PK-05/PK-06/RT-15 by itself. A supported real implementation needs full state-domain compatibility and rollback, executable activation/recovery, complete provider/PTY/write exclusion and independent security review before the updater may become available.
