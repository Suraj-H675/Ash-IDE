## Product and dependency boundary

The native Ash CLI already excludes general application-plugin command handlers and specs. However, `tsc` still emitted `out/cli/plugin-authoring/` (**21 JavaScript files**) and `out/cli/plugin-dev-watch/` (**8 JavaScript files**), and the desktop package carried both directories. A read-only import-graph audit of the **newest tested** baseline ASAR established that the only literal CJS consumers of `plugin-authoring` were three files **inside** `plugin-dev-watch`; no surviving packaged file imported `plugin-dev-watch`. The old command handlers had already been explicitly excluded. The canonical checkout's older `dist/` was **not** used as the package reference.

Added both exact directories to `EXCLUDED_ASH_CLI_ARTIFACT_ROOTS` in `config/excluded-ash-cli-entry-artifacts.cjs`, excluded their complete trees from `config/electron-builder.config.cjs`, and taught `verify-ash-packaged-asar-hygiene.cjs` to reject their presence in **either app.asar or app.asar.unpacked** and to fail closed if a retained packaged JS module literally imports either tree. Existing application-plugin CLI entrypoint exclusions and the mobile/relay static-import protection remain. **No browser extension, provider-native skill/MCP, native agent, local Git, terminal, editor, or Chromium code was removed.**
