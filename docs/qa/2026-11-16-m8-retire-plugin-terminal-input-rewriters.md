## Boundary and design

The inherited Main runtime terminal input layer used general application-plugin hooks (`terminal.send` and `agent.prompt.before`) to intercept and potentially rewrite normal terminal text and agent prompts, with an extra per-terminal decision queue. Ash has already excluded the general application-plugin worker, preload RPC namespace, marketplace and startup. Keeping this wrapper in live PTY delivery was dead execution complexity and an inappropriate interception point for a terminal-first local IDE.

The normal `sendTerminal` and `sendTerminalAgentPrompt` methods now **forward the original handle, input and options** directly to the retained delivery methods in `terminal-input-dispatch.ts`. The new `terminal-direct-input.ts` is the base for the existing agent-prompt serialization runtime chain. The old `AfterPluginHooks` method names have been replaced by `deliverTerminalSend` / `deliverTerminalAgentPrompt`, including their recursive restored-pane paths.

**Retained:** controller-proven PTY liveness checks, restore/reattach admission, terminal input size limits, launch composer admission, terminal and agent-prompt payload formatting, agent-prompt generation pinning, per-generation `serializeAgentPromptSubmission` ordering, stale handle and permission refusal, explicit provider-native status/hooks, Codex/Claude integration, browser and local runtime persistence. The removed plugin-decision queue had no pending decisions without a running app-plugin host; retained prompt serialization is a separate active safety mechanism. No user content, saved settings, process state or credentials were migrated.

Deleted three inherited Orca files (`terminal-send-plugin-hook.ts`, `terminal-plugin-hooked-input.ts`, and their obsolete plugin-queue test) and recorded **their exact pinned original SHA-256s** and exclusion reasons in `docs/provenance/ash-exclusions.json`. New direct-input behavior tests replace plugin queue tests, without weakening the real prompt/PTY runtime suites.
