## Dependency-traced implementation

The preceding M8 milestone removed general application-plugin custom-editor choices from the live file panel, content surface, view-mode toggle and file tabs. An importer trace then found a closed **nine-file** legacy editor-frame and merge group: the orphan `PluginCustomEditorFrame` and `PluginBytesCustomEditorSurface`, plugin-only desktop notice, guest-frame event handler, guest document host, guest-merge acknowledgement controller, external-change merge store, plugin reload/flush adapter, and the plugin-specific `CustomEditorExternalChangeBanner`.

One dependency remained **active**: normal text editing still rendered `CustomEditorExternalChangeBanner`, a wrapper that could hide the normal disk-change warning whenever the old plugin merge store marked the file busy. Ash no longer mounts that merging plugin editor. The normal `EditorEditFileSurface` now imports and renders the **retained `ExternalFileChangeBanner` directly** for changed-on-disk text files, so an excluded plugin state cannot suppress the file recovery warning.

Deleted nine inherited Orca files with **exact pinned original SHA-256s and individual reasons** recorded in `docs/provenance/ash-exclusions.json`. **Preserved:** built-in Monaco, Markdown, CSV/notebook/SVG, image/media and binary-file fallback, text external-change warning with Compare/Reload/Keep and overwrite consent, editor-buffer save/stale-write protection, the `editor-bytes-documents` draft/rekey/save queue, its `CustomEditorBinaryDocument` type and the editor frame flush coordinator. The byte-draft state remains deliberately retained for a separate no-data-loss/recovery audit rather than assuming it is safe to delete. Browser extensions and native provider hooks/skills/MCP were not changed. No real user file, account, browser profile, secret or other application's data was edited.

## Remaining acceptance limitations
