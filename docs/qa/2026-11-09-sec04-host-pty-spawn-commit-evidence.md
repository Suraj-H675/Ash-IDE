# SEC-04 — host PTY spawn commit evidence

This milestone adds a main-process-only, in-memory receipt for a fresh local PTY after the shared spawn commit succeeds and the host pane binding is persisted. The receipt binds the provider-returned PTY ID and incarnation to the persisted worktree/tab/leaf pane, and stores only a SHA-256 hash of the effective launch token. It is bounded to 256 receipts per runtime, rejects duplicate PTY/incarnation keys, survives GUI surface closure, and retires on PTY exit or bounded eviction.

Other agents and ordinary shells, adopted panes, provider reattachments, remote/daemon/WSL routes, refused or synthetic exits, mismatched provider results, missing token/incarnation, and stale or absent persisted pane bindings do not produce receipts. No renderer, RPC, preload, CLI startup, account-router, provider-hook, or daemon behavior changed. `canAshWriteProviderGlobalHooks()` remains `false`.

Account attribution is deliberately unresolved: `accountEvidence` is `missing` because host-verified authenticated Claude account identity is not frozen alongside the effective process environment. The receipt is not connected to the dormant Claude correlation state machine. SEC-04 account-to-PTY correlation and AG-05/AG-07 acceptance remain open.

A `claude` command recognition is a non-authoritative classification hint, not proof that the provider process ever reached an authenticated Claude login. The recorder additionally refuses a PTY that synchronously reports exit while the runtime exit listener is being registered.

The existing terminal launch result path still carries its pre-existing raw `launchToken` field for current launch handling; this receipt adds no token field to that response, logging, renderer events, or snapshots. Removing that existing field would require a separate compatibility change to the launch-result contract.

## Review correction: source-defined command eligibility and observer atomicity

Independent GPT-6 Luna/xhigh read-only security review found two P2 issues in the first feature commit `c29a4526`: (1) the broad preflight regex also recognizes `echo claude` even when no Claude CLI is the direct command, and (2) an exception thrown by PTY exit-listener registration left an unobserved map entry and could bypass the 256-entry bound. The feature is **not eligible for main integration** until both are repaired and verified.

The recorder now requires the planned launch-agent label and provider launch-agent label to be exactly `claude`, the saved launch command and both prepared/effective command strings to be conservative direct `claude` invocations, and no shell override, renderer-delivered command, pipeline, substitution, compound command or ambiguous wrapper. This is deliberately a *narrow consistency classification*, **not** proof of the physical process image or authenticated Claude account. An otherwise valid Claude start with unusual quoting/wrappers can fail to produce dormant evidence; ordinary terminal startup remains unaffected. The recipient never sees or uses this receipt for authorization.

Exit-observer registration now either succeeds or removes its newly inserted record before returning false. A new regression repeats **260** distinct failed PTY subscriptions and checks every receipt is absent, preventing a stale receipt or capacity-limit bypass. A separate test covers immediate exit during registration. Daemon rejections report `daemon-runtime` distinctly from WSL; negative cases now assert their precise reasons rather than any refusal. The positive integration fixture uses disposable `HOME` and `CLAUDE_CONFIG_DIR` so the normal Claude trust flow never writes real provider files; the existing Vitest real-agent-home guard stays enabled. The runtime spawn/commit fixture exercises direct Claude, `echo claude`, a shell wrapper, a compound command and a conflicting saved launch configuration against the production preflight/commit path with a fake local PTY.

The integrator independently reran **32/32** tests for the recorder, **37/37** focused PTY and runtime integration tests, and **181/181** tests across 15 Claude/PTY/security suites, plus all Node/renderer TypeScript projects after these changes. Native Claude cases use disposable homes and a fake loopback provider, not authenticated provider accounts. Earlier local results on `c29a4526` remain valid evidence for its unchanged paths but **do not substitute** for CI on the follow-up commit; the final 15-suite security regression and feature CI must be separately observed. Both native and type-aware Oxlint, Oxfmt, source-provenance (33,506 upstream file records, 212 Ash adaptations, 8,260 documented removals), Ash CLI build, and Electron desktop bundle passed locally. The existing bundle emitted chunk-size and ineffective-dynamic-import warnings. The P2 corrective work still requires a second independent security reviewer disposition and successful GitHub CI for its exact new commit before acceptance. Full authenticated account identity, root hook provenance, persistent daemon evidence, packaged GUI testing, and SEC-04/AG-05/AG-07 acceptance remain open.
