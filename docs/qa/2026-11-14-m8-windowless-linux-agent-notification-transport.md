## Gap and implementation

- Existing execution-host agent transition tracking emits a settings-gated `agent-task-complete` / needs-input event when the authoritative GUI is closed. Previously `TerminalAgentPhonePush` only dispatched the retained notification stream, so a local persistent **Node runtime** (whose desktop surface is intentionally inert) did **not** produce an OS banner by itself. This is a real source-level gap against RT-12.
- A windowless producer now also requests an OS banner for **eligible** agent completion/input news. It uses the existing window-ownership, disabled-notification, muted-workspace, coordinator-only, and burst cooldown gates; desktop-owned events continue through the existing Electron path, without another local banner. It does **not** reintroduce a vendor mobile push service, cloud gateway, scheduled agent, or network listener.
- If an Electron desktop surface is available, native Electron `Notification` remains first choice. On Linux, when that surface cannot serve a Node execution host, a small fallback calls fixed `/usr/bin/notify-send` with `--` separating user text from options, **without a shell**. It uses only local session D-Bus/display environment keys, not `PATH` or provider credentials; limits title/body length, suppresses subprocess stdout/stderr and bounds helper lifetime to 3 seconds. Missing D-Bus, unsupported OS, missing helper and rejected delivery return **false**, not fabricated success.
- On Debian/Ubuntu, `notify-send` is in **`libnotify-bin`**, not just the library `libnotify4`. Added a required `.deb` dependency; Arch host's `/usr/bin/notify-send` comes from `libnotify`. Portable AppImage installations on other distributions still require a working **local notification daemon** and the system helper. macOS/Windows Node-runtime native delivery is not implemented by this Linux-only fallback.

## Acceptance boundary and remaining work

- **Implemented:** Linux native notification fallback for existing windowless agent completion/input events, settings gating and no-GUI duplication prevention; local native system-helper and D-Bus transport verified. **Verified:** fresh AppImage under native X11 and Wayland for browser/PTY/clipboard/runtime behaviors. **Not yet accepted:** a full **real authenticated agent completion while the GUI is closed** from the packaged app, including the terminal transition -> Node runtime event -> OS D-Bus notification delivery in one observation. The producer is validated with synthetic lifecycle rows and the notifier with the isolated bus, not a real provider in a closed-window run. Therefore **RT-12 remains PARTIAL / OPEN**, not PASS. No real provider account, token or user repository was accessed in this milestone.
- A working local notification daemon and D-Bus session are necessary. `notify-send` absent on an arbitrary AppImage host means truthful unavailable delivery. Other desktop OSes, packaged RPM (missing host `rpmbuild`), full PK-02/PK-03, notification sounds/click-to-focus, ordinary window-manager notifications and visual parity remain open.
- New source and QA tests are included in GitHub foundation workflow; **the exact post-push CI conclusion must be independently observed**. Do not count an earlier successful CI run as proof for this change. No existing desktop/notification center was changed: every native notification in the QA journey went to a **private** D-Bus service.
