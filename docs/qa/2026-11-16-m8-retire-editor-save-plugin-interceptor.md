## Consumer-traced implementation

Although Ash had already removed the general application-plugin host, its Main editor-save IPC registrar, and the preload `plugins` namespace, the active editor save queue still invoked `editorSavePluginHook` after format-on-save on explicit saves. The inherited worker protocol could change the written text or deny a save. A separate save-attempt handler still recognized the plugin-specific denial exception and presented it as an active feature.

**Removed:** the active `editor.save.before` app-plugin transform and save-denial branch. The `editorSaveTransform` pipeline now returns the existing `editorFormatOnSave` result directly; it still validates the queued invocation, resolves the same operation mutation context, and asserts file-write authority and the discard epoch through the unchanged formatter callback. The same queue controls saved text and disk preconditions. A save-error branch now handles stale files, non-UTF-8 text, and byte-document update refusal without importing the deleted app-plugin denial class. The original plugin-only source file `editor-save-plugin-hook.ts` is deleted, with its pinned original SHA-256 and specific exclusion reason recorded in `docs/provenance/ash-exclusions.json`.

**Preserved:** built-in editor/Monaco, asynchronous format-on-save behavior, explicit user/autosave/restart/overwrite saves, stale-operation refusal, pending-buffer flush, format-before-write ordering, UTF-8 conversion approval, byte-document safeguards, original-folder-first file targets and normal error notices. The change neither installs nor accesses provider accounts, modifies a user's repositories, nor touches Chromium extensions or provider-native skills/MCP/hooks.

## Remaining acceptance boundary

This closes **the live general app-plugin editor save interceptor**, not the entire M8 exclusion. Dormant custom-editor iframe/byte-document frame paths, plugin-specific UI/worker and shared contract modules, and removed-feature compatibility sources still require dependency-safe review. The new tests verify save transforms and errors, but are **not** full native GUI editing/saving of a real file; the native tests verify the packaged GUI, browser and terminal lifecycle, not real-provider permission prompts or editor visual parity. Multi-window stress, updater rollback, native macOS/Windows builds, signing and full M8/EX-03/ED-07/PK-08 acceptance remain **OPEN**.
