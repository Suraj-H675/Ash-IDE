## Reviewed entrypoint boundary

Despite prior M8 startup, Settings, CLI, renderer, and plugin-view exclusions, the Electron `contextBridge` still exposed `window.api.plugins` with general plugin installer, marketplace, approval, command, panel worker, source-resolution, content-pack, update, and status methods. A web fallback separately fabricated a partial plugin API and would manufacture callable fallbacks for unknown namespaces. This was a real preload-attack-surface and excluded-product mismatch even when the Main-side plugin service had not started.

**Change:** Remove the `plugins` property and entire import of its IPC bridge from the real Electron preload; remove the synthetic web plugin API; make the web fallback explicitly return `undefined` instead of a callable proxy for `plugins`. Retain a **type-only optional** `PreloadApi.plugins?: PluginsApi` compatibility slot while orphaned Orca modules are still imported in the source tree. Those modules now call an explicit `requireLegacyAppPluginsApi()` guard and fail with an unsupported-feature error if reached, **not** a success-shaped installer stub. This is temporary technical debt, not a working app-plugin API.

Two actively retained mechanisms have independent missing-API behavior: plugin command replacements dispatch the **built-in** action immediately if the plugin host is absent; plugin-syntax grammar loading fails explicitly rather than invoking missing preload methods. Built-in Monaco syntax continues to work; the excluded general plugin-syntax provider is not restored. Tests exercise the retained built-in command fallback with synthetic historical metadata.

Removed four now-unreferenced inherited Orca source files and recorded their exact pinned source SHA-256 values in `docs/provenance/ash-exclusions.json`: desktop `plugins-bridge.ts`, `plugin-panel-push-bridge.ts`, web `web-plugins-api.ts`, and obsolete `PluginPanel.fixture.tsx`. Core Chromium extensions, native/provider-oriented skills/MCP/hooks, browser/terminal/updater APIs and the local runtime were not removed.

## Remaining exclusions and limits

**EX-03 / EX-10 / PK-08 are not fully accepted.** Many inherited app-plugin renderer views, API types, custom editors, source providers, compatibility and Main-side modules still exist. The type-only optional `plugins` contract and the temporary guarded legacy-source adapter are **intentional, reviewable follow-up debt**, not advertised capabilities. The new ASAR gate verifies the **preload** contains no `plugins:*` channels; it does not prove every app-plugin Main handler or bundled renderer chunk is gone. Full visual parity, actual provider-authenticated flows, independent-window stress, Windows/macOS native release tests, updater rollback and signed releases were **not** performed here.

No personal repository, credential, provider account, other app profile or pinned upstream checkout was changed. Candidate packaging evidence is independent from integration. Fast-forward integration, post-integration tests, push and exact successor GitHub CI must be observed separately; the green CI link above belongs to the **base** SHA.
