## Audited scope and safety decision

The approved Ash product excludes app-managed mobile pairing/push/relay and remote SSH host deployment, but retains local authenticated runtime IPC, built-in editor/browser, native chat, Git-over-SSH and provider-native tools. Before this change, the actual Linux `app.asar` still contained **5,168 entries** including many compiled mobile/remote-runtime compatibility modules, even though app-level mobile/remote entrypoints were already disabled. A conservative static import scan of **4,630 shipped compiled JS modules and 7,428 detected relative import edges** identified a subset of candidates with no required packaged JavaScript importers. This is *not* evidence that every remote-named module is disposable: examples such as `out/shared/mobile-markdown-document.js` support real local file operations, `out/shared/mobile-bridge-frame-bytes.js` is used in native-chat frame budgets, and remote-client error helpers can be used by local services. Those remain in the package.

**This milestone removes 16 individually reviewed compatibility/test modules**, covering dormant mobile notification types, mobile edit and E2EE test fixtures, mobile-web capabilities, relay status/phone protocol/close reasons, an unused remote shared-control test server, and a shipped remote-host test fixture. See the exact path list in `config/excluded-ash-mobile-relay-artifacts.cjs`. It additionally rejects the entire `out/mobile-web`, `out/relay`, `out/remote-host` and `resources/mobile` service trees, plus separately copied `mobile` or `relay` native resource directories. No wildcard removes retained local IPC, browser extensions, Git commands or all `out/shared/remote-runtime` modules.

The exact file selection is shared by the electron-builder `files` exclusions and an independent `afterPack` verifier that checks both `app.asar` and `app.asar.unpacked`; the verifier also blocks excluded top-level service trees and native resource roots. A second packaging-time check parses **static literal** `require`, `import()` and import/export references from retained compiled JS and rejects any direct dangling import of the 16 removed modules. It is deliberately not claimed to analyze arbitrary computed dynamic import paths. Synthetic negative tests cover every listed forbidden file in ASAR, representative unpacked files, native roots, and CommonJS/ESM dangling imports. A real `app-builder-lib` matcher test verifies that the file exclusions actually work, while explicitly retaining local CLI, Markdown, native chat, daemon and browser-extension helpers.

## Remaining acceptance boundary

This closes **one dependency-reviewed executable packaging slice of EX-01, EX-02 and PK-08**, **not** all three gates. Much legacy remote-control, pairing and E2EE source and compiled shared/chunk code remains; some of it is shared by valid local workflows. It requires independent reachability, listener, browser and runtime checks before larger removal. Mobile/remote UI entrypoints, the absence of external listeners and full bundled feature exclusion are not being globally re-certified here. Mac/Windows package builds, target-distribution dependency resolution, active app version rollback, native provider-authenticated completion and full visual parity remain separate release gates. No real user provider account, host package installation, project repository or global desktop was modified, and no release was published.
