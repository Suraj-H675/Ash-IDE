## Runtime ownership change

The previous milestone removed Jira/Linear from the active and broad RPC/CLI registries, but both connectors were still constructed by the actual Ash process. Jira's `RuntimeJiraCommands` was instantiated by the shared browser/emulator `RuntimeEdgeCommandController` and its `jira*` methods were bound onto the runtime object with `Object.assign`. Linear's `OrcaRuntimeWithLinearCommands` layer instantiated `RuntimeLinearCommands` for every runtime and `installRuntimeLinearCommandSurface` installed its methods on the final runtime prototype, even though they had no supported Ash RPC/CLI consumer.

This slice removes those construction roots without rewriting the browser or emulator behavior. `OrcaRuntimeWithStateFields` now extends the existing `OrcaRuntimeWithFileCommands` directly, the installed-surface type no longer advertises Linear, and the final runtime no longer installs the Linear prototype facade. The edge controller no longer creates/binds Jira, but still binds its full browser and emulator surfaces. Its terminal-driver host no longer injects an otherwise-unused Jira environment callback.

Thirteen pinned, byte-verified upstream Orca files were retired: the three now-orphaned runtime facade files, five Jira/Linear RPC handler/helper files and five corresponding obsolete test suites/fixtures. The exact upstream SHA-256 of every deletion is recorded in `docs/provenance/ash-exclusions.json`; current adapted-source hashes are updated in `docs/provenance/ash-modifications.json`. This deletion is **not** a relaxation of an Ash acceptance gate: the handlers are intentionally excluded and their old tests required the removed methods to exist. A replacement negative test checks the actual runtime prototype, live edge-command surface, absent RPC/facade roots, and presence of historical saved-state test coverage; existing active RPC-registration tests continue to check that no Jira/Linear API is exposed.

Jira saved filters, `taskResumeState`, attachment-image utility/tests, shared issue-reference schemas, stored repo/worktree metadata and credential migration paths remain intact; they were not reset or migrated. Ordinary Git/GitHub/GitLab, terminal, browser, emulator, account, provider-agent and manual orchestration capability remains in the source. Dormant `src/main/jira`, `src/main/linear`, and auxiliary Linear implementation classes **still exist** and need a later dependency-grounded audit. Do not represent this as complete removal of all Jira/Linear source.
