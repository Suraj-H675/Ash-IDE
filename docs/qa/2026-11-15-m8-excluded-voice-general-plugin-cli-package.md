## Source-backed release issue

The source pack classifies general IDE plugin marketplaces/worker hosts and speech/dictation as **excluded** (EX-03, EX-08), while deliberately retaining Chromium browser extensions, built-in Monaco language support, and provider-native skills/MCP/hooks. The earlier `verify-ash-packaged-asar-hygiene.cjs` gate already rejected unrelated application SDKs and Jira/Linear command modules. However, direct inspection of the **actual** previously accepted packaged `app.asar` found **17 compiled, separately loadable speech and general plugin CLI entrypoints** despite Ash's supported local `ash-ide` CLI not exposing either product feature. The package also retains broader shared/renderer/main plugin source, which requires **separate audit and removal** before claiming full EX-03 acceptance.

## Changes

- Removed legacy `speech` and `plugin` command registrations from both `COMMAND_SPECS` and `ASH_COMMAND_SPECS` by removing their imports in `src/cli/specs/index.ts`, and removed lazy speech/general-plugin handler groups from the dispatcher. Removed both command roots from main's executable-command recognition list. Did **not** remove retained `terminal`, `runtime`, browser or provider-native code.
- The retained `serve` command was still importing `findAppSpeechRecognizerDir`, as caught by the real packaged-CLI dependency closure on the first AppImage attempt. Removed that caller and the optional `speechRecognizerDir` arg from the local orcad launch. `serveWithOrcad` now forcibly sets `ORCA_SPEECH_RECOGNIZER_DIR` to the **empty string**, preventing inherited ambient environments from unintentionally selecting another app's speech-addon copy. This preserves the normal local CLI host path.
- Added a deliberately exact, centrally reviewed list `config/excluded-ash-cli-entry-artifacts.cjs` of **17** previously emitted compiled speech/general app-plugin CLI entries. `electron-builder` excludes each from `app.asar` and `app.asar.unpacked`, with the same paths independently enforced by the existing `afterPack` ASAR hygiene verifier; no wildcard removal of browser extensions, provider-native MCP, or built-in syntax code.
- Extended the packaged ASAR hygiene suite with explicit packed/unpacked negative fixtures and added `excluded-speech-plugin-command-registration.test.ts`. Registered the new source regression in foundation CI, while retaining existing package hygiene CI tests.

## Remaining acceptance

This is a verified **CLI + packaged entrypoint exclusion slice**, **not full EX-03 / EX-08 / PK-08 acceptance**. Remaining bundled general plugin hosts, renderer assets, shared contracts, speech-related shared helpers, remote-management code, mobile contracts and internal telemetry-looking modules require explicit graph and runtime audit; some similarly named modules are retained infrastructure and must not be removed based only on string matches. Build both macOS/Windows distributions and repeat native tests separately before accepting cross-platform exclusion. We did not rebuild RPM/DEB in this CLI-only slice; the same source config filters will be tested for those targets at the next 3-target release gate. This controlled-hook test does not execute a real authenticated provider CLI. No package or release was signed, installed or published.

Git integration, post-merge packaged checks, push, and exact new hosted CI are **separate subsequent evidence** and must not be assumed from the baseline run.
