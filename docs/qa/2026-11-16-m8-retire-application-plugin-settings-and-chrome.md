## Product boundary and implementation

Ash excludes the general application-plugin host, marketplaces, and plugin-supplied editor contributions, but retains Chromium extensions, provider-native skills/MCP/hooks, built-in syntax, and ordinary keyboard remapping. Even after app-plugin startup was disabled, the inherited renderer still advertised a **Plugins (Alpha)** Settings navigation entry, mounted the old plugin manager on that page, exposed a Plugins status-bar button and plugin-contributed status-bar items, dispatched `view.plugins` from global shortcuts, and offered **Open Plugins** in the shortcut editor.

Removed those active consumer paths from the Settings nav builder, Settings section renderers, main Settings page, status-bar surface, keyboard dispatcher, and shortcut action handlers. Normal shortcut Settings now filters the obsolete `view.plugins` action, while the old shared keybinding ID remains parseable for already-persisted overrides; no new binding or invocation is exposed. The normal Settings **Appearance** and **Privacy** pages, provider-native agent skill controls, status-bar updater, and terminal settings remain.

This deliberately **does not** remove all inherited plugin source, shared keybinding metadata, the preload plugin bridge, remaining Appearance theme-catalog installation affordances, link/deep-link compatibility, or every plugin-themed renderer chunk. In particular, `PluginInstallTrustDialogHost` remains at Settings page level because the current Appearance theme flow still references the legacy installation dialog; that separate dead path needs its own dependency-safe removal. No user settings or credentials were migrated or written.
